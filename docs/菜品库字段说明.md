# 菜品库字段说明 — `dishes_yangtze_pearl_delta.csv`

长三角（沪苏浙）+ 珠三角（广府，含港澳）**日常常吃菜品**库，供 `meal-decision`
项目或其他会话直接作为训练数据集的「动作属性表」使用。

- **文件**：`dishes_yangtze_pearl_delta.csv`（UTF-8 with BOM，CRLF 友好，可直接被 `pandas.read_csv` 读取）
- **规模**：295 道菜 / 16 个品类
- **地域**：珠三角 135 · 两地共通 82 · 长三角 78
- **生成脚本**：`_gen_dishes_lr.py`（可复现；内部共整理 448 道，按「日常高频」裁剪到 295，
  被裁掉的 153 道宴席名菜/长尾变体全部列在脚本末尾输出里，需要扩库时改配额即可）

---

## 1. 列定义（16 列）

| 列 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `dish_id` | int | 0..294 | 主键，连续、唯一 |
| `dish_name` | str | — | 标准菜名，唯一无重复 |
| `category` | str | 16 类（见 §2） | 用于两层模型的**第一层品类** |
| `region` | str | `长三角` / `珠三角` / `共通` | 地域归属；`共通` = 两地都高频 |
| `time_cost` | int | 3..90 | 出餐+吃完所需分钟数 |
| `price` | int | 4..108 | 单人份价格（元，2024 前后一线/新一线水平） |
| `spicy` | int | 0..3 | 0=不辣 1=微辣 2=中辣 3=很辣 |
| `heavy` | int | 1..5 | 厚重油腻感，1=清爽 5=很顶 |
| `healthy` | int | 1..5 | 健康度 |
| `temperature` | int | 0/1/2 | 0=凉/冷食 1=温热 2=热食 |
| `carb` | int | 1..5 | 碳水含量 |
| `protein` | int | 1..5 | 蛋白质含量 |
| `taboo` | str | 见 §3 | **过敏原**，多值用 `!` 分隔 |
| `is_veg` | int | 0/1 | 1=纯素（无肉无海鲜无蛋奶） |
| `meal_slots` | str | 见 §4 | 适合时段，多值用 `/` 分隔 |
| `frequency` | int | 2/3 | 1=偶尔(已裁掉) 2=常吃 3=日常高频（几乎每周） |

> **`taboo` 与 `is_veg` 是刻意分开的两个维度**：`taboo` 只放**过敏原**，
> 素食用独立的 `is_veg` 布尔列。这样「素食」诉求不会和数据里的一道菜重合，
> 也不会让「肉」这种标签污染过敏原字段。

## 3. `taboo` 过敏原字段（重要）

- **分隔符是 `!`，不是逗号** —— 刻意为之，避免与 CSV 的字段分隔符冲突导致引用混乱。
- 实际出现的取值只有 4 个：`海鲜`(40) · `麸质`(77) · `乳制品`(29) · `花生`(6)；
  172 道为空（无过敏原）。28 道是多值，如 `海鲜!麸质`、`乳制品!麸质!海鲜`。
- `牛肉`、`素食`、`坚果` 等其他取值在本库中**未使用**，不要写进词表（见 §6）。

```python
# 读取示例
td = df.taboo.fillna("").astype(str)
has_shellfish = td.str.split("!").apply(lambda xs: "海鲜" in xs)
```

两条来自调研、值得注意的标注约定：

1. **含蚝油/豉油/虾皮的菜已打 `海鲜`**。因此「蚝油生菜」「白灼菜心」这类
   看起来是素菜的条目带 `海鲜` 标签——这是刻意的（蚝油=牡蛎）。
   但它们 `is_veg=0` 吗？不：`蚝油生菜` 的 `is_veg=0`，`白灼菜心` 是 `1`（不勾蚝油）。
   已校验：**`is_veg=1` 的 50 道菜中，0 道带 `海鲜`、0 道带 `乳制品`**，
   8 道带 `麸质`（烤麸、吐司、拌面等，属正常）。
2. **酿造酱油/蚝油/柱候酱多由小麦酿造**，所以卤水、豉油鸡、煲仔饭等
   实际含麸质，已按此打标。若要严格区分，可后续再拆
   `allergen_mandatory` / `allergen_custom` 两列。

## 4. `meal_slots` 取值

固定 5 个 token，与 `features.py` 的 `CTX_VOCAB["time_slot"]` 完全一致：

```
早餐 / 午餐 / 下午加餐 / 晚餐 / 夜宵
```

多值用 `/` 分隔（如 `早餐/下午加餐`）。已做过一致性校正：
**炒菜、大菜不再出现 `早餐`**（原先「清炒芥兰」「麻婆豆腐」等误带早餐时段，已剔除）。

## 5. `frequency` 与「名菜 ≠ 日常菜」

这是本库最重要的一条设计依据。调研取证发现：

> 浙菜中的**西湖醋鱼、宋嫂鱼羹、龙井虾仁、清汤越鸡**……**浙江人平时根本就不会吃这些菜，
> 这些菜只有在大的饭店里才会吃到**。

**名气与日常消费频率在长三角是负相关的。** 因此：

- `frequency=3`：几乎每周吃（156 道）
- `frequency=2`：常吃（139 道）
- `frequency=1`：偶尔／宴席名菜／长尾地方变体 —— **已从本库裁掉（153 道）**，
  包括西湖醋鱼、松鼠桂鱼、响油鳝糊、烤乳猪、盆菜、上汤焗龙虾，
  以及大量只在单一地级市流行的面条变体（枫镇大肉面、嵊州榨面、常山索面……）。

广式一侧的日常性分级（来自广府调研）：

- **A 级 几乎天天可遇**：白切鸡、叉烧、豉汁蒸排骨、白灼菜心、老火汤、肠粉、云吞面、
  烧鹅濑粉、番薯糖水
- **B 级 每周常见**：煲仔饭、艇仔粥、啫啫煲、卤水拼盘、干炒牛河
- **C 级 节庆/宴席**：烤乳猪、盆菜、上汤焗龙虾、鲍鱼 —— 已裁掉

**如果你的训练目标是「日常吃什么」，就只保留 `frequency=3`（156 道）；
若要覆盖请客/节庆场景，就把 `_gen_dishes_lr.py` 里的配额放宽，把 `frequency=1` 的 153 道放回来。**

## 6. 接入 `meal-decision` 需要改的地方

原有 `artifacts/dishes.csv` 是 47 道 / 8 品类，本库是 295 道 / 16 品类。
`features.py` 读列名与下面这批常量，**必须同步修改**，否则会静默错配：

### 6.1 `features.py` 必改项

```python
# 1) taboo 词表 —— 用本库实际出现的 4 个过敏原，不要沿用旧的含“素食”的词表
CTX_VOCAB["taboo"] = ["", "海鲜", "乳制品", "麸质", "花生"]

# 2) category 会自动从 dishes.csv 推导（CATEGORIES = sorted(...unique())），
#    品类从 8 变 16，N_CAT 自动更新，无需手改；但要重新训练模型。

# 3) 数值归一化区间 —— 本库实测范围仍落在原区间内，可不动：
CTX_NUM_RANGE = {"available_time": (0.0, 150.0), "hunger": (1.0, 5.0)}
DISH_NUM_RANGE = {"price": (0.0, 100.0), "time_cost": (0.0, 70.0)}
#  本库 price 4~108（略超 100，超出部分归一化会 >1，属可接受；
#  想要精确可改成 (0.0, 120.0)）
#  本库 time_cost 3~90（同上，可改成 (0.0, 100.0)）
```

### 6.2 合并两个库（保留原有 47 道 + 新增 295 道）

```python
import pandas as pd

old = pd.read_csv("meal-decision/artifacts/dishes.csv")          # 47 道
new = pd.read_csv("dishes_yangtze_pearl_delta.csv")              # 295 道

old = old[["dish_name", "category", "time_cost", "price", "spicy", "heavy",
           "healthy", "temperature", "carb", "protein", "taboo"]]
new = new[["dish_name", "category", "time_cost", "price", "spicy", "heavy",
           "healthy", "temperature", "carb", "protein", "taboo"]]

merged = pd.concat([old, new], ignore_index=True)
# taboo 分隔符统一为逗号（旧库用逗号，新库用 !）—— 二者都行，只要 features.py 一致
merged["taboo"] = merged.taboo.fillna("").astype(str).str.replace("!", ",", regex=False)
merged = merged.drop_duplicates(subset="dish_name").reset_index(drop=True)
merged.insert(0, "dish_id", range(len(merged)))
merged.to_csv("meal-decision/artifacts/dishes.csv", index=False, encoding="utf-8-sig")
```

### 6.3 改完之后必须重新训练

- `N_DISH` 从 47 → 300+，`dish_id` embedding 表随之变大 → 旧的 `model.npz` 权重全部作废。
- `N_CAT` 从 8 → 16，`CuisineNet` 输出维度变了 → **必须重跑 `train.py`**。
- `build_dataset.py` 里的 `DISHES` 是硬编码元组列表，与 `dishes.csv` 是**两份数据**。
  要么改 `build_dataset.py` 让它读 CSV，要么把新库同步进那个列表；两边不一致会
  导致 `samples.csv` 里的 `dish_name` 对不上 `dishes.csv`。
- 品类内候选池从 6 变成 8~28。第二层的 listwise softmax 在更大的候选池上
  更难收敛，**建议把训练轮数上调，并用验证集排序损失选轮次**（不要用 top-1 命中率，
  原 README §6 已说明该指标无区分度）。

## 7. 两地的口味差异（可直接引用）

- **长三角**：浓油赤酱、油多味浓糖重色艳、咸中带甜；主食偏**面食**（江浙吃面强度很高）。
  绝大多数菜**不辣**；例外是**徐州**（江苏最辣，"咸鲜中带明显辣香"）与
  浙江**建德**（"虽地处江南，口味却不似杭帮菜那么柔和齁甜，反而以'辣'出名"）。
  苏锡、杭帮最甜。
- **珠三角**：清鲜爽嫩滑、追求本味、**几乎不用辣**；主食以**米制品**为核心
  （河粉/米粉/濑粉/粿条/肠粉）。**最核心差异在汤**——广府"宁可食无菜，不可食无汤"，
  老火汤是灵魂；长三角汤品多为菜式附庸。
- **辣度分布（本库实测）**：不辣 242 · 微辣 31 · 中辣 10 · 很辣 12。
  很辣的 12 道中，10 道是外来菜（麻辣烫、串串香、冷锅串串、冒菜、水煮鱼、烤鱼、
  四川麻辣香锅、小龙虾、牛油麻辣火锅、酸辣粉），只有
  **麻婆豆腐、小炒黄牛肉**是已进入日常的川湘菜。

## 8. 数据局限（请知悉）

1. **无逐条配方来源**。菜名与地域归属有调研来源支撑，但
   `time_cost / price / heavy / healthy / carb / protein` 是**人工估算**，
   不是实测营养数据。用于建模够用，做营养学结论不够。
2. **`healthy` 的口径未统一**。广式老火汤的扣分点在**嘌呤**（广东省中医院营养科
   明确建议减肉量或先"飞水"），而长三角菜更多是**油/糖**。同一个 `healthy=3`
   在两类菜里含义不完全相同。
3. **深圳、珠海本地菜缺失**。调研未取到足够正文来源，本库的"珠三角"实质是
   **广府（广州/佛山顺德/东莞/中山/香港/澳门）**。
4. **`price` 是一线/新一线城市水平**，且为单人份估价，不同城市差异可达 ±40%。
5. **山东/福建系快餐（黄焖鸡、沙县）标为 `共通`**，它们是全国化的外来品类，
   不代表本地传统口味。
