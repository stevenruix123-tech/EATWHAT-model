# 容量扫描结论：当前模型没有容量提升空间

## 这是什么

在独立目录 `capacity-study/` 里做的隔离实验，**不改动 `meal-decision/` 的任何文件**。
本目录自带一份 `build_dataset.py` / `train.py` / `features.py` 副本，数据集在本目录下
用同一 seed 独立生成（317 道菜 / 18 品类 / 2000 情境 / 7340 行，与主线完全一致）。

## 实验设置

- 只改两个容量旋钮，其余超参与 `train.py` 完全一致：
  - `id_dim` = `dish_id_emb` 维度（主线硬编码为 **8**）→「每道菜的个性化自由度」
  - `hidden` = `DishScorer` MLP 隐层宽度（主线为 **48**）
- 60 轮 / 固定 seed=7 / 固定数据 / 固定划分
- 逐轮记录**验证集 top-1 与 top-3**（对照 gold），并把 forward / backward 分开计时
- 计划 12 个配置，实际完成 **8 个**（用户要求提前停止，`id_dim=64` 与 `id_dim=4/16` 之外未跑完的已放弃）

## 结论：没有提升空间

1. **8 个配置的末 20 轮 top-1 全部落在 67.8%~72.1% 这 4.3 个百分点的带子里**，
   而基线自身逐轮波动的 sd 就有 0.88%。用「2×sd」当显著性阈值，
   能勉强算超出的只有 5 个，且**最大优势 +3.66%（参数量是基线的 2.14 倍）**。
   4% 的差距对应 283 个验证情境里约 10 个情境 —— 不足以支撑"该加容量"的结论。

2. **`id_dim` 几乎不起作用**：4 维（9,976 参数）与 8 维（11,436 参数）
   末 20 轮 top-1 相差 **0.04%**。说明模型基本不靠"背下每道菜"取胜，
   而是靠 11 个菜品属性做判断 —— 这正好解释了它为什么在没见过的雪天情境上不退化。

3. **加大 `hidden` 只买到时间成本**：同一 `id_dim` 下 h96 相比 h48
   每轮慢 **+2.0 ~ +3.8 秒（约 +45%~+70%）**，换来的 top-1 提升仅 0~3%，
   且 id16_h48（-0.57%）与 id16_h96（+3.00%）方向相反，说明是噪声。

4. **收敛速度也不区分容量**：首次达到 val top-1 ≥ 50% 的轮次全部落在第 4~7 轮，
   8 个配置没有差别。

5. **更硬的证据是主线测试集的后悔值**：平均效用 0.6493 / 理论最优 0.6724，
   后悔值只剩 0.0231。品类内最优与次优的真实效用差中位数只有 0.0075 ——
   剩下的差距主要是数据集里那 12% 的"随手选"噪声，不是模型容量装不下。

## 本目录文件

| 文件 | 说明 |
|---|---|
| `cap_run.py` | 单配置运行器（参数化 id_dim/hidden，逐轮记录 top-1/top-3 与分段计时） |
| `sweep.py` | 扫描调度器（计划 12 配置，先跑完的 8 个） |

| `results/id*_h*.json` | 每个配置的逐轮明细（含每轮 fwd/bwd/train/total 秒数） |
| `results/summary.json` | 扫描过程中的累积结果 |
| `artifacts/` | 本目录独立生成的数据集（含 `samples.csv`、`scenario_utility.npy`） |

## 局限（如实说明）

- **单 seed**。所有配置只跑了 seed=7，没有做多 seed 重复，
  所以"4% 以内算噪声"是基于逐轮波动 sd 的推断，不是严格的初始化方差估计。
  要把结论钉死，应补 3~5 个 seed 取均值。
- **8/12 配置**。`id_dim=64` 以及部分组合未跑完（用户要求提前停止）。
  但趋势已很清楚：`id_dim` 从 4 到 32 涨了 8 倍，指标没动。
- **验证集只有 283 个情境**，所以 1% 的 top-1 差异 ≈ 2.8 个情境，
  分辨率有限。主线报告里的测试集指标（309 情境）同理。
